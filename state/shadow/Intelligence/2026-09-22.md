## OpenAI：消費者の利用基盤から、企業の仕事を動かす基盤へ

基準日：2026年9月21日。再調査・改稿：9月22日（日本時間）。以下は会社発表、製品仕様、分析を区別した企業資料です。随時更新される料金表だけは9月22日の確認値を明記します。

### 会社の全体像

OpenAI は ChatGPT を個人・法人に提供し、開発者にはモデル API とエージェントの実行機能を販売しています。企業に対する接点は、従業員が使う ChatGPT、開発者が使う Codex、自社製品に組み込む API の三つです。同社はこの接点を統合する方針を示しており、モデルを選ぶだけでなく、仕事を開始して結果を受け取る場所を提供しようとしています。[事業・資金調達の説明](https://openai.com/index/accelerating-the-next-phase-ai/)

この会社を理解するうえで押さえるべき点は、既に大きな消費者基盤を持つことと、その規模を企業向けの継続収益へ移す途中であることです。3月31日の自社公表では ChatGPT の週間利用者は9億人超、有料契約者は5,000万人超、法人事業は売上の40%超でした。これは公表当時の値で、9月の実績や監査済み決算ではありません。[同発表](https://openai.com/index/accelerating-the-next-phase-ai/)

**現在の評価は、企業向け製品の幅と販売力は強い一方、それが利用企業の利益や OpenAI 自身の持続的な利益にどれだけ結び付くかは別途確認が必要、というものです。** 製品の提供は確度が高く、優位が長く続くという評価は中程度です。収益・利用の公表には当事者の利害があり、顧客維持率や利益率を同じ基準で比較できる資料が不足しています。

### 製品、顧客、提供形態

| 製品・機能 | 顧客が購入するもの | 事業上の役割 |
|---|---|---|
| ChatGPT／法人向けプラン | 会話、調査、資料作成などを行う利用環境 | 個人の日常利用から企業契約につながる入口 |
| Codex | コードベースを読み、変更・確認を進める開発用エージェント | 開発者の継続利用と実務への接続 |
| GPT-6 Astra | 9月3日から段階提供された、コンピューター操作・専門業務・開発を扱うモデル | 難しい仕事を任せられる範囲を広げる上位製品 |
| Agents API | 9月10日公開ベータ。Codex の実行機構を使ったクラウドエージェント | セッション、ツール、実行環境の管理を企業の実装に取り込む |
| Astra for Law | 9月17日発表。法務向け検索・指示・文脈を加えた Astra | 業界の業務に近い層で直接販売とパートナー販売を広げる |

出典：[Astra](https://openai.com/index/gpt-6-astra/)、[Agents API](https://openai.com/index/introducing-the-agents-api/)、[法務向け発表](https://openai.com/index/astra-for-law/)。Astra for Law には Harvey、Legora のような API 顧客も含まれます。業界向け製品の拡張は、既存の業務ソフト会社と競合する可能性と、それらの会社の供給元になる可能性を同時に持ちます。

Agents API は長いセッション、ツール利用、複数エージェントの仕事を扱います。実行環境は OpenAI ホストだけでなく、自社環境やパートナー環境を選べます。基盤となる Codex のコードを公開する方針も示しています。[公開時の仕様](https://openai.com/index/introducing-the-agents-api/)

ここから読み取れるのは「実行環境の選択肢がある」ことです。モデルやセッション履歴、認証、評価を含むシステム全体が他社へ無加工で移せることまでは意味しません。逆に、管理サービスを使うだけで必ず囲い込まれるとも断定できません。移行の難しさはどの機能に依存するかで変わります。

### 価格と利用企業の費用

9月22日に確認した公式 API 料金表の Standard・短いコンテキストの価格です。単位は100万トークン当たりの米ドル。入力・出力とも通常料金で、キャッシュ、長いコンテキスト、Batch、Fast mode、ツール等の費用は別条件です。

| モデル | 入力 | 出力 | 読み方 |
|---|---:|---:|---|
| GPT-6 Astra | $10 | $50 | 最上位の能力に高い単価を付ける |
| GPT-5.6 Sol | $4 | $20 | 少なくとも11月21日までのプロモーション価格 |
| GPT-5.6 Terra | $2 | $12 | 中間の価格帯 |
| GPT-5.6 Luna | $0.20 | $1.20 | 大量処理を検討できる低価格帯 |

[公式料金表](https://developers.openai.com/api/docs/pricing/)。この表を9月15日時点の価格確認として遡及利用しません。旧版にあった Sol の割引終了後の確定価格や、二次集成由来の追加料金は、ここでは断定していません。

価格差は利用企業の選択に直結します。例えば単価の高いモデルでも、再試行や人の手直しが少なければ仕事一件当たりでは安くなる場合があります。一方で、高い推論設定、長いセッション、確認待ちを含めると支出が増えることもあります。広告レポート、コード変更、社内資料作成を同じ「1トークン」で比較しても業務の採算は分かりません。納品物の合格率と人の確認時間まで含めて選ぶ必要があります。

### 売上、資金、計算資源

3月31日、OpenAI は1,220億ドルのコミット済み資金と、資金調達後評価額8,520億ドルを公表しました。同時に月間売上20億ドル、約47億ドルの未使用リボルビング融資枠を説明しています。調達額・評価額・月間売上・融資枠はそれぞれ違う量です。調達額を売上、評価額を手元資金として扱ってはいけません。[資金調達発表](https://openai.com/index/accelerating-the-next-phase-ai/)

同発表で示す計算資源の調達先には Microsoft、Oracle、AWS、CoreWeave、Google Cloud があり、半導体も NVIDIA を中心に複数の方式を組み合わせています。顧客には統一された製品を提供しながら、供給元は分散させる構造です。供給の確保は成長を支えますが、契約額や設備規模だけで利益を評価することはできません。

分析上の争点は、利用拡大に伴う収入が、推論費用・研究費・インフラ負担を上回るかです。規模が大きいほど単価が下がる経路と、能力向上や安全監視のため計算量が増える経路が併存します。9月3日の安全説明では、Astra のツール利用時の監視に相応の計算費用をかけると公表しています。[Astra の安全説明](https://openai.com/index/safety-overview-gpt-6-astra/)

### 能力と運用上の制約

Astra の発表は、コンピューター操作、専門業務、科学、開発における性能向上を中心にしています。掲載されたベンチマークや顧客の初期評価は、能力が広がった根拠にはなりますが、あらゆる企業で人の仕事を代替できる実績ではありません。与えた道具、試行回数、推論設定、合格条件が変われば結果も変わります。[能力評価](https://openai.com/index/gpt-6-astra/)

OpenAI は Astra のサイバー能力を自社の Preparedness Framework で Critical と評価し、安全対策と監視を強化しました。同時に、書かれた推論の監視しやすさが Sol より低下した試験結果も開示しています。モデルが賢くなることと、全ての行動を監督しやすくなることは一致しません。[安全説明](https://openai.com/index/safety-overview-gpt-6-astra/)

利用企業への含意は、許可範囲、外部への書き込み、機密情報へのアクセス、異常時の停止を仕事ごとに設計する必要があるということです。事業に組み込んだ後の停止や制限変更は、単なる使い勝手の問題から納期・顧客対応の問題に変わります。

### 競争上の位置と別の解釈

OpenAI の強みは、消費者の利用基盤と開発者の仕事場を持ち、モデル・実行管理・業界向け機能を同じ提供元で揃えられることです。企業は部品を組み合わせる負担を減らせます。その反面、提供元の仕様変更に業務が左右される範囲も広がります。

| 説明 | 支える材料 | この説明だけでは説明できないこと |
|---|---|---|
| 企業の標準的な仕事場へ進む | ChatGPT、Codex、Agents API、法務向け製品が同じ業務につながる | 発表だけでは契約更新・利益・業務完了率を証明できない |
| 顧客の実装負担を減らす共通部品になる | 自社・パートナーの実行環境を選択でき、業務ソフト企業にも供給する | 履歴・運用・評価の移行まで容易とは限らない |
| 利用規模を維持するため製品と資金を拡張している | 大きな資金需要、広い価格帯、複数の供給元 | 拡張が苦しい採算の結果なのか、成長投資なのかは公表値だけでは決まらない |

現時点では最初の二つが同時に進んでいると読むのが妥当です。「閉じた独占」か「完全に開いた部品」かの二択にすると、実行環境の開放とサービスへの依存が同居する実態を見失います。

## Anthropic：企業の実務に入り込み、能力と利用条件を一緒に売る

基準日：2026年9月21日。再調査・改稿：9月22日（日本時間）。財務数値は公表当時の会社説明として扱い、年率換算売上、実際の年間売上、調達額を分けます。

### 会社の全体像

Anthropic は Claude のモデル、会話型サービス、開発用の Claude Code、一般業務向けの Cowork、API を提供する会社です。基盤モデルだけでなく、仕事を継続して進める道具と、その仕事を安全に任せるための利用条件を企業に提供しています。研究と製品の両方を進め、資金調達発表でも安全性・解釈可能性の研究、計算資源、製品・提携の拡張を資金用途に挙げています。[5月28日の会社説明](https://www.anthropic.com/news/series-h)

企業にとっての選択肢は、Claude を直接契約することだけではありません。同社は AWS、Google Cloud、Microsoft Azure の3大クラウドでの提供を説明し、AWS を主なクラウド提供元・訓練パートナーと位置付けています。[同発表](https://www.anthropic.com/news/series-h)

**現在の評価は、企業が難しい仕事を任せる供給元として製品と販売経路を広げているが、高い能力ほど利用条件・監督・供給制約が事業の一部になっている、というものです。** 製品と契約上の仕組みは一次資料で確認できます。顧客の利益改善や、全クラウドで同じ条件を提供できるかの評価は限定的です。

### 販売経路と導入の実態

クラウド3社で買えることは、既存の調達・請求・情報管理を使いたい企業にとって利点です。ただし、同じ Claude の型名でも、特別なアクセス制度、公開の時期、管理機能が一致するとは限りません。9月17日開始の生命科学向け制度は、初期段階で Anthropic の直接 API と Enterprise／Team が対象で、第三者プラットフォームには未対応でした。[LSVP の提供範囲](https://www.anthropic.com/news/life-sciences-verification-program)

企業への入り方は API のセルフサービスに限りません。7月9日には UST との提携を公表し、半導体・自動車・製造業などの設計・検証環境に Claude を組み込み、世界で2万人の技術者等を訓練する計画を示しました。2万人は訓練計画の対象規模で、既に2万人全員が業務成果を出したという実績ではありません。[UST との取り組み](https://www.anthropic.com/news/ust-claude)

この販売方法は、業務を知る提携先が導入の負担を引き受けるという点で、単にチャットの席を売る方法とは異なります。利用企業から見れば、モデルの比較に加えて、既存の工程に接続できる人と管理体制がいるかを比較することになります。

### 能力の実績をどこまで読めるか

6月18日の Project Fetch は、Claude をロボットを伴う作業に使った試験です。共通する4作業について、AI 側9分35秒、人間側181分・361分という比較を示しました。ただし研究者による接続・承認・進行補助があり、試行も限定されています。特定の作業を速くできた根拠であって、研究職全体を約20倍・40倍速くした実績ではありません。[Project Fetch 第2段階](https://www.anthropic.com/news/project-fetch-phase-two)

Opus 5 や Sonnet 5 の発表も、複数の開発・知識業務の評価と初期顧客の証言を示しています。実務への適用範囲が広がっていることは読めますが、提供元が選んだ評価と成功例が中心です。会社としての導入判断では、難しい失敗例、停止した作業、手直しを含めると成果が残るかが重要です。

### 安全性、アクセス条件、運用の制約

8月31日、Anthropic は7月30日に報告した3件の無許可アクセスと、8月4日に英国 AISI が報告した別件への対応を公表しました。問題のモデルは評価のためサイバー安全策を外しており、前者には第三者評価環境の誤設定がありました。外部の未公開モデルのサイバー評価を停止し、内部評価は対策後に再開したと説明しています。通常の全顧客向けサービスが一律停止したという意味ではありません。[対応説明](https://www.anthropic.com/news/improving-alignment-security-efforts)

事業上の意味は、能力の高いモデルを配るときに、評価環境、利用者の権限、異常を止める監視まで提供条件になることです。独立レビューとして METR との作業を計画していますが、この発表時点でレビュー完了を確認したわけではありません。

9月17日の LSVP はこの構造を具体化しています。資格・安全体制等を審査し、チーム単位の Standard Use と、特定の研究案件を対象に追加審査する High-risk Use を分けます。他の安全策は維持し、対象トラフィックの30日保存を求めています。早期利用は数十組織が参加済みという会社説明で、「初週に数百組織」は見込みです。[制度の条件](https://www.anthropic.com/news/life-sciences-verification-program)

利用企業は、能力が必要な仕事について、直接契約・クラウド経由の違い、保存条件、権限の更新、監督担当を確認する必要があります。安全策が負担になる場合と、従来使えなかった業務へのアクセスを可能にする場合の両方があります。

### 競争上の位置と代替説明

| 説明 | 根拠 | 判断を弱める条件 |

## Google／DeepMind：検索・業務ソフト・クラウドを通じて AI を供給する

### 会社と事業の全体像

Google の AI 事業は、Gemini という一つのアプリに閉じていません。検索・YouTube の広告、Workspace の業務利用、Google Cloud の計算資源と企業向けサービス、Gemini の直接利用にまたがります。Google DeepMind のモデル開発を、既存の顧客接点とクラウドに配る構造です。[2026年7月22日の CEO 決算説明](https://blog.google/company-news/inside-google/message-ceo/alphabet-earnings-q2-2026/)

**現在の評価は、既存事業の規模と AI の供給網を同時に持つことが強みであり、AI を売る収入と、既存製品を AI で強くする収入を分けて見る必要がある、というものです。** 「Gemini の企業採用データがないので何も分からない」という旧版の整理は誤りでした。利用と事業成長を示す資料はあり、分からないのは主に Gemini 単独の利益・市場シェア・利用企業の成果です。

### 規模、成長、投資

7月22日の第2四半期決算説明では、Alphabet 全体の売上成長率は前年同期比24%、Search and Other は17%、YouTube Ads は13%、Cloud は82%と公表しています。Cloud の受注残は5,140億ドルです。受注残は将来の契約収入に関わる指標で、その四半期の売上や現金とは異なります。[CEO 決算説明](https://blog.google/company-news/inside-google/message-ceo/alphabet-earnings-q2-2026/)

同資料の利用規模は、Gemini アプリ月間9.5億人、Antigravity 週間240万人超、モデル API 毎分約220億トークン、Gemini Enterprise は Fortune 100 の約90%が利用というものです。アプリの人数、開発ツールの人数、処理量、企業数は別の母集団なので足し合わせられません。企業数だけでは全従業員への展開や有料利用の深さも分かりません。[同説明](https://blog.google/company-news/inside-google/message-ceo/alphabet-earnings-q2-2026/)

6月3日の投資家向け説明では、第1四半期 Cloud 売上約200億ドル、営業利益約70億ドル、利益率約33%、2026年の設備投資見込み1,800〜1,900億ドルを説明しました。これらは6月時点の対象期間・予算で、9月の更新値と混ぜません。[投資家説明](https://blog.google/alphabet/investor-presentation-june-2026/)

読み取れるのは、AI は既に売上を持つ事業の中で拡大しており、投資規模も大きいことです。Cloud 売上には計算資源、他社モデル、データや業務サービスも含まれるため、Cloud 成長率を Gemini 単独のシェア上昇率に置き換えることはできません。一方で、顧客の企業数と API の利用量を無視し、全てを他社モデル向けのインフラ需要と決めつけることもできません。

### 価格と導入の費用

### 競争の強みと制約

Google は利用者との接点、モデル開発、独自の計算基盤、法人販売を同時に持ちます。AI が検索の利用を増やすなら広告にも利益が及び、企業が Gemini 以外を選んでも Cloud の資源が使われる可能性があります。この複数の収益経路は、モデル API を売る事業だけとは異なる強みです。

ただし、既存事業を持つことは調整の難しさも生みます。検索体験の改善が広告や外部サイトへの送客とどう両立するか、モデル性能の更新を全製品へどう配るか、膨らむ設備投資の回収をどう進めるかが論点です。利用者数が増えても、利益の増え方を同時に見る必要があります。

| 説明 | 支える事実 | 反対の材料・未確定部分 |
|---|---|---|
| 既存製品への AI 統合が成長を増幅する | 検索・Cloud の売上成長、Gemini と Antigravity の利用 | 同じ顧客群の因果効果や Gemini 単独利益は未開示 |
| Cloud の需要全体が伸び、Gemini の成功とは一部別に進む | Cloud は多様な基盤・サービスを含む | Gemini Enterprise の導入や自社 API 利用もあり、他社需要だけでは説明できない |
| 管理機能の統合で企業の移行費用が上がる | 業務データ、権限、実行管理が同じ環境へ集まる | 公開モデルや共通形式もあり、顧客が依存箇所を減らせる余地はある |

現在は一番目と二番目を分けて追うのが妥当です。売上と利用の観測があることは確かですが、そこから一つのモデルが企業市場を独占すると結論づける材料はありません。

Grok 4.6 の発売時価格は100万トークン当たり入力 $2、出力 $6 からで、Fast 版は2倍と説明されています。7月16日の Grok 4.5 も入力 $2、出力 $6 で公表されています。能力を上げても基本単価を据え置くという見せ方です。[4.6](https://x.ai/news/grok-4-6)、[4.5](https://x.ai/news/grok-4-5)

4.6 の発表では、Artificial Analysis Intelligence Index が61、Terminal-Bench v3.0 が26%など、評価ごとに異なる結果を示しています。全体指数が競合と同等でも、個別の開発作業では差が残ります。比較対象の数字は各社公表や公開順位表を含むため、全モデルを同じ実行環境で再試験した独立比較とは区別します。[評価表と注記](https://x.ai/news/grok-4-6)

利用企業にとっては、安い単価と低い仕事の費用は同じではありません。コード変更ならテストに通るまでの回数とレビュー時間、資料作成なら事実確認と修正時間を足して比較する必要があります。旧版にあった異なる Grok 世代の価格や、分母が不明な「幻覚率」を混ぜて優劣を決めることは避けます。

### 公開コードが意味すること

Grok Build のコード公開日は7月15日です。公開対象はモデルの重みそのものではなく、文脈を組み立て、モデルの応答から道具を呼び、端末画面を表示する実行側の仕組みです。公式発表はローカルの推論先へ向けて実行できることも説明しています。[コード公開](https://x.ai/news/grok-build-open-source)

これは利用者が内部の動作を調べたり、モデルを差し替える構成を試したりできる材料です。一方で、公開コードがあることだけで、ホスト型サービスの運用、サポート、全ての連携機能を同条件で再現できるとは限りません。モデル本体、実行ソフト、ホスティング、販売経路を分けて評価する必要があります。

競争への含意は、企業が管理サービスに依存せず使える部分が増えることです。同時に xAI は、その公開ソフトで使われるモデルや自社サービスを販売できます。公開と商業化を二者択一にする必要はありません。

### 資金と計算資源、実際の負担

1月6日、xAI は Series E で200億ドルを調達したと発表し、NVIDIA と Cisco Investments を戦略投資家に含めています。発表は2025年末の Colossus I・II を合計100万 H100 相当超と表現しています。「相当」は計算能力の換算であり、100万枚の同一チップを実数確認した意味ではありません。[資金調達発表](https://x.ai/news/series-e)

6月5日の目論見書では、AI 部門の営業損失は2025年63.55億ドル、2026年1〜3月24.69億ドル。調整後 EBITDA も同四半期はマイナス6.09億ドルです。これは非 GAAP の調整指標で、営業損失やキャッシュ消費額と置き換えられません。本文はクラウド費、GPU 減価償却、データセンター、人件費などを負担増の要因に挙げています。[目論見書 §5.4.4.3、§5.4.5.3（冊子123〜124頁）](https://content.spacex.com/cms-assets/FINAL_Documents%20and%20Updates/SpaceX%20-%20EU%20Prospectus%20%28Approved%20by%20Bafin%29%20-%20June%205%2C%202026.pdf)

ここからは「資金の情報がない」ではなく、「大きな投資負担が開示されている」と読むべきです。低価格の提供が新規利用を呼び、その利用から費用を回収できるかが事業の争点になります。SpaceX に入ったことは資源を組み合わせる余地を生みますが、AI 部門の負担が消えるわけではありません。

### 制約と競争上の位置

計算資源が多いことは、学習やサービス供給の選択肢を増やします。しかし、電力・冷却・施設の許認可・設備稼働、顧客需要、モデル性能が揃って初めて収益につながります。AI 部門が大きな損失を計上している以上、GPU の規模だけで持続可能性を評価できません。

消費者接点では X、開発者接点では Cursor などの外部ツール、実行基盤では公開した Grok Build を使えます。これは自社アプリへの集客だけに依存しない利点です。一方、他社ツール経由の利用は、利用者が同じ画面で別モデルへ切り替える余地も大きくします。安い価格が使い続ける理由になるか、難しい仕事での品質が理由になるかを区別して追う必要があります。

| 説明 | 支持する事実 | 判断を変える条件 |
|---|---|---|
| 低価格と外部販売で利用を増やす | 4.5・4.6 の価格、複数の販売先 | 同価格でも品質不足で使われない、値引きを止めると利用が消える |
| 公開ソフトで自社の利用圏を広げる | Grok Build のコード、プラグイン、ローカル推論 | 公開版の利用が増えても Grok の収益につながらない |
| 資源の規模で能力と供給を押し上げる | 調達、Colossus、SpaceX への所属 | 設備費用と稼働の差、損失拡大、供給制約が続く |

最初の二つは製品の設計から確認できる方向です。三つ目が事業として成功するかは、費用と利用の両方の実績が必要です。

## ByteDance：消費者向けの配信・制作と、企業向け AI を並行して広げる

基準日：2026年9月21日。再調査・改稿：9月22日（日本時間）。製品仕様は公式資料、資金調達は確認した報道として区別します。中国向けと海外向けの提供条件を一括りにしません。

### 会社と AI 事業の全体像

ByteDance は TikTok、Douyin、CapCut、TikTok Shop、Lark／Feishu など、コンテンツの閲覧・制作・商取引・仕事の接点を持つ会社です。AI 事業は、Doubao の利用サービス、Seed のモデル開発、TRAE の開発環境、火山引擎（Volcano Engine）の法人向け提供、動画・画像生成にまたがります。[会社の製品一覧](https://www.bytedance.com/)、[Seed2.0 の提供先](https://seed.bytedance.com/en/blog/seed-2-0-official-launch)

**現在の評価は、日常の消費者利用と企業の処理需要を別々の経路で取り込み、文章・コード・映像まで広く供給している会社、というものです。** 既存製品の顧客接点は強みです。ただし、Doubao の人数が増えれば法人 API の利益も増える、という関係が自動的に成立するわけではありません。両方の収入と費用を分けて見る必要があります。

製品の供給と開発の進展は確度が高く、中国外での収益化・各 AI 事業の利益については中低程度です。公開財務の粒度が米国上場企業と異なり、アプリの人数や収益に関する推計には定義の差があります。

### モデルの能力と、読み違えてはいけない比較

Seed2.1 は、複数の道具・環境にまたがる業務、要件確認から実装・検証までの開発、画像・動画の理解を中心に説明しています。社内評価と公開評価を組み合わせ、最も難しい自由度の高い仕事には改善余地が残ると認めています。単発の回答より、資料を読んで仕事を完了することへ重点を移しています。[6月23日の発表](https://seed.bytedance.com/en/blog/seed2-1-officially-released-advancing-ai-productivity)

2月の Seed2.0 発表は Pro・Lite・Mini と Code を用意し、性能に対するトークン価格が業界上位モデルよりおよそ一桁低いと主張しました。これは発表時の会社比較です。9月の他社モデル、最新の Seed2.1、地域別の販売価格まで同じ優位が続くという証拠ではありません。[Seed2.0 発表](https://seed.bytedance.com/en/blog/seed-2-0-official-launch)

低価格の効果を判断するには、同じ資料・同じ合格条件で、再実行や人の確認も含めて比較する必要があります。日本語の業務、専門用語、顧客の情報管理条件が加わると、公式の総合順位だけでは選べません。用途別の成功率を確かめれば、全部を一つのモデルへ集めず、文書の大量処理と難しい判断で使い分ける余地があります。

### 動画・画像の事業上の意味

Seedance 2.5 は、最大30秒の音声付き動画生成に加え、画像30枚・動画10本・音声10本までの参照、時間位置を指定した編集を説明しています。7月31日時点では Jimeng AI、Doubao Pro 等への提供開始とし、BytePlus ModelArk の API は今後提供と書いています。発表の「提供予定」をその日の API 稼働実績にしてはいけません。[Seedance 2.5 発表](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5)

広告や制作の仕事では、生成の長さよりも、同じ人物・商品・音・画角を維持し、依頼された箇所だけ直せるかが採算に関わります。制作ツールや配信先を既に持つ ByteDance は、モデルを制作工程へ近づけやすい位置にいます。ただし、良いデモから、顧客の承認、権利処理、配信後の売上までを飛び越えて評価することはできません。

生成の品質が上がると、試作品や複数案の制作費が下がる可能性があります。一方で、その節約を顧客への値下げに渡すのか、作る本数を増やすのか、制作会社の利益に残すのかは市場の競争で変わります。これが、モデル性能だけでなく広告・制作業の構造まで追う理由です。

### 資金、設備投資、採算

9月4日の Reuters の独自取材は、ByteDance が約30行から296億ドルの融資を確保したと報じています。関係者によれば、当初200億ドルから増額、無担保、当初3年で2年延長の選択肢があり、中国外の案件に使うとされています。同記事時点では署名は近く予定とされ、会社は取材に直ちには回答していません。[Reuters 配信記事](https://uk.marketscreener.com/news/bytedance-secures-29-6-billion-loan-in-ai-push-sources-say-ce785bdad189f22c)

このため、本資料は融資条件を契約原本で確認済みとは扱いません。とはいえ、金額・期間・用途を伴う報道は、資金の規模を判断する材料です。融資が供給拡張を支える説明と、返済・設備稼働の負担を増やす説明を両方残します。銀行の参加数や融資規模は、AI 事業が既に利益を出している証拠ではありません。

旧資料の Doubao 日間利用者2億人超、日収100万元未満、月間利用者約610万人減という数字は、第三者推計の引用が重なり、対象・期間・収益の範囲を揃えられていません。これらを計算して一人当たり採算や会社の損失を確定させることはしません。採算の判断に必要なのは、アプリの課金、法人 API、制作サービスを分けた継続的な収入・費用です。

### 地域と提供条件の制約

中国の火山引擎と、海外向けの BytePlus ModelArk は、提供モデルや公開時期を同一と仮定できません。例えば Seedance 2.5 の発表自体が、アプリでの公開と海外 API の予定を分けています。日本の企業が採用を判断する際は、契約する提供面、利用できるモデル、保存・処理地域、商用利用条件を確認する必要があります。

権利処理も制作の一部です。Seedance 2.0 の公式説明は、実在人物の参照に本人確認または事前の適法な許諾が必要と明記しています。この注意は、全ての生成物や素材について権利が保証されるという意味ではありません。実際に使う版とサービスの条件を読み、人物・音声・商品素材を持ち込めるかを業務側で確かめる必要があります。[公式の参照素材に関する説明](https://seed.bytedance.com/en/blog/seedance-2-0-official-launch)

## AI市場：仕事を実行する仕組みと、利益を受け取る場所の競争

基準日：2026年9月21日。9月22日に一次資料を再調査して再構成。仕様を後日確認した箇所は確認日を明記します。対象は主要5社と、それらを支える供給・制度・労働市場です。世界の全事業者を網羅した市場シェア調査ではありません。

### 現在の市場構造

**競争の対象は、モデルが回答できることから、顧客のデータを使って仕事を実行し、その利用を継続してもらうことへ広がっています。** OpenAI の Agents API、Anthropic の Claude Code／Cowork、Google の Antigravity と企業向け基盤、xAI の Grok Build、ByteDance の TRAE／Coze は、形は異なっても作業の実行に関わる製品です。[OpenAI](https://openai.com/index/introducing-the-agents-api/)、[Anthropic](https://www.anthropic.com/news/claude-sonnet-5)、[Google](https://blog.google/company-news/inside-google/message-ceo/alphabet-earnings-q2-2026/)、[xAI](https://x.ai/news/grok-build-open-source)、[ByteDance](https://seed.bytedance.com/en/blog/seed2-1-officially-released-advancing-ai-productivity)。

顧客にとって重要なのは、モデル単体の試験点数に加え、必要なデータを読めるか、権限を守って操作できるか、失敗を検出できるか、監督込みで安くなるかです。供給企業にとっては、その仕事の入口、実行環境、計算資源のどこを売上にできるかが争点です。

| 層 | 提供するもの | 主な位置にいる企業 | 競争と利益の論点 |
|---|---|---|---|
| 計算資源 | GPU・TPU、電力、設備、クラウド | Google、Microsoft、AWS、Oracle等。xAIも自社設備 | 大きな固定費を稼働と契約で回収できるか |
| モデル | 言語・画像・音声・動画の能力 | 本資料の5社など | 品質を保った仕事当たり費用と供給条件 |
| 実行と管理 | 複数段階の作業、権限、監督、接続 | Agents API、Claude、Googleの企業基盤、Build、Coze等 | 運用負担を減らす対価と、移行の難しさ |
| 顧客の仕事場 | 開発、法務、広告、社内業務、制作 | 自社サービスとCursor・Harvey等の提携先 | 顧客関係・業務データ・成果の責任を誰が持つか |
| 消費者への配信 | 検索、対話、SNS、動画、商取引 | ChatGPT、Google、X、ByteDanceの各サービス | 発見される場所と需要を作る力 |

同じ会社が複数の層にいます。モデルを別会社へ替えられても、顧客データや監督の手順を別の実行環境へ移す費用が残ることがあります。逆に、外部モデルを選べる顧客接点はモデル供給者に対する交渉力を持ちます。

### 価格競争と、実務で支払う費用

Sonnet 5 は8月10日の公式訂正で100万トークン当たり入力2ドル・出力10ドルを恒久化しました。Grok 4.6 は8月12日の発表で入力2ドル・出力6ドルからです。モデル間でトークンの切り方、思考量、品質、速度、キャッシュ条件が異なるため、出力単価だけで順位を決められません。[Sonnet 5](https://www.anthropic.com/news/claude-sonnet-5)、[Grok 4.6](https://x.ai/news/grok-4-6)。

同品質の仕事当たり費用は、モデル利用料、外部ツール、再試行、人の確認・修正、接続と運用、失敗時のやり直しを含みます。例えば安いモデルで3回やり直す仕事と、高いモデルで1回で終わる仕事では単価の優劣が逆転します。これは計算の考え方であり、本資料で各社の業務費用を実測した結果ではありません。

利用者が得られる利益は、安くなった分を販売価格に渡すか、粗利に残すか、新しい仕事を受けるかでも変わります。広告・制作・開発では、生成量が増えても顧客の予算や注意が同じなら、成果物単価だけ下がる可能性があります。需要が増えたかを、処理量とは別に測る理由です。

### 安全と制度が変える提供条件

### 仕事と所得について既に分かること

Stanford の8月12日改訂研究は、米国ADPの給与データを2026年6月まで分析し、AIへの露出が高い職種の22〜25歳の雇用が、露出の低い同年代と同じ伸びをした場合より19%少ないと報告しました。主に採用減であり、経済全体の大量失業を確認したという結論ではありません。教育を考慮すると差が縮むなどの限界があり、著者も因果効果の推定と区別しています。[研究概要](https://digitaleconomy.stanford.edu/publication/canaries-in-the-coal-mine-six-facts-about-the-recent-employment-effects-of-artificial-intelligence/)。

日本のJILPT調査は、2024年に雇用者2.2万人へ行ったWeb調査を2025年5月に公表したものです。AI利用者では仕事の質について改善の回答が悪化を上回り、訓練や労使の対話との関連も示しました。自己申告の過去の調査であり、2026年の全国の雇用効果ではありません。[調査No.256](https://www.jil.go.jp/institute/research/2025/256.html)。

両者は矛盾とは限りません。既に職に就く利用者の仕事が改善しながら、新人の入口が狭まることはあり得ます。企業の生産性だけを見ていると、この違いを見逃します。日本の広告・開発・管理業務については、新人求人、採用、総労働時間、実質賃金、転職後所得を別々に確認すべき段階です。

### 期間別の判断と見直し条件

短期1〜3か月は、業務ごとの品質・確認時間・供給条件を比較します。実行基盤の機能が増えたため試す価値はありますが、顧客データと手順の移行費用まで契約前に測ることが重要です。中期3か月超〜1年は、試験から本番への移行、顧客維持、利益、採用を追います。利用量増加だけで利益が残らない場合、需要拡大という評価を「処理量の拡大」に限定し直します。

長期1年超〜3年では、時間短縮が需要と所得に届くか、顧客接点・計算資源の所有者へ利益が偏るかが分岐です。若年採用の回復と実質賃金の上昇が広がれば補完の説明が強まり、採用減と利益集中が続けば分配と移行の問題が大きくなります。個人については非公開の所得実績がないため、本人の改善・悪化を代入していません。

## 5つの未来：現在の証拠から、仕事・利益・生活の分岐を読む

基準日：2026年9月21日。9月22日に再構成。これは9月21日時点に発行した確率予測ではなく、公表済み資料を用いた後日の評価です。5つの未来は同時に進み得るため、確率を合計100%にしません。

### 現在の位置

**AIを使う入口と実行機能は拡大しています。一方、その利益が雇用・所得へ広く届く経路は、まだ一方向に決まっていません。** 供給企業の売上・投資、製品の価格や公開コードは観測できます。労働面では既存の利用者の改善と、若年採用への圧力が併存する材料があります。給付や所有構造の転換は、今回の資料だけでは実施の広がりを確認できません。

| 世界像 | 現在の証拠が支える範囲 | 判断を超えてはいけない範囲 |
|---|---|---|
| W1 人とAIで仕事の需要が広がる | 作業を支援する製品、利用者の改善、企業向け需要 | 全国の採用・実質所得が一律に増えるとは未確認 |
| W2 AIや顧客接点の所有者に利益が集中する | 大規模投資、仕事場とモデルの統合、条件を決める力 | 高売上や高評価額を、そのまま高利益・独占としない |
| W3 知的作業が安く広く使える | 低価格のモデル、公開された実行コード、制作機能の普及 | 実務の総費用や小企業の利益改善は別途必要 |
| W4 仕事以外の仕組みが生活を支える | 雇用移行を支える必要性を示す材料 | 支援の必要性は、給付が実施・利用された証拠ではない |
| W5 所有と分配のルールが変わる | 監査・公共関与の議論と制度化 | 安全規制や企業買収を、公共・共同所有の実現に数えない |

数値の確率を置いていないのは判断を放棄するためではありません。どの段階まで証拠があるかを明示し、後の実績で変えられる判断にするためです。

### W1：補完から、新しい需要と仕事へ

この経路は、AIが作業の一部を短縮し、人が顧客理解・責任・判断を担い、価格低下や新しい提供物で需要が増える場合に成立します。需要の増え方が必要な労働時間の減り方を上回れば、雇用も増え得ます。単に同じ納品物を少人数で作るだけなら、企業の利益が増えてもこの経路の後半は成立しません。

支持材料には、企業の仕事を実行する Agents API や Claude、Google の法人利用があります。日本のJILPTの2024年労働者調査も、AI利用者の仕事の質の改善と訓練・対話の関係を報告しています。[Agents API](https://openai.com/index/introducing-the-agents-api/)、[Google決算説明](https://blog.google/company-news/inside-google/message-ceo/alphabet-earnings-q2-2026/)、[JILPT](https://www.jil.go.jp/institute/research/2025/256.html)。

逆方向の材料は、米国ADPを用いたStanfordの研究です。AIへの露出が高い職種の若年層の雇用は、低露出の同年代を基準とする比較で弱く、主に採用に差が出ています。これは全雇用の消滅でも日本の因果効果でもありませんが、「生産性向上なら自動的に全員の雇用も改善する」という説明を弱めます。[8月改訂の研究](https://digitaleconomy.stanford.edu/publication/canaries-in-the-coal-mine-six-facts-about-the-recent-employment-effects-of-artificial-intelligence/)。

短期は完成品質と確認時間、中期は新しい受注と新人採用、長期は移行後所得と実質賃金が分岐です。人の役割が高度化したという企業説明だけで、入口の職が減った問題を解決済みにしません。

### W2：供給と顧客接点を持つ企業へ利益が集まる

AIを実行するための設備と、顧客が普段使う画面の両方に規模の利点があれば、利用が増えるほど一部の供給者に交渉力が集まります。モデルの単価が下がっても、運用・管理・配信をまとめて売る会社が利益を取ることは可能です。

Google の検索・Workspace・Cloud、OpenAI の ChatGPT・Codex、ByteDance の制作・配信の接点は、この経路を考える材料です。OpenAI と Anthropic の大型調達、Google の設備投資計画は、参入に必要な資本が大きいことも示します。[OpenAI](https://openai.com/index/accelerating-the-next-phase-ai/)、[Anthropic](https://www.anthropic.com/news/series-h)、[Google投資家説明](https://blog.google/alphabet/investor-presentation-june-2026/)、[ByteDance](https://www.bytedance.com/)。

ただし資本集中と利益集中は同じではありません。SpaceX のAI部門の営業損失は投資回収の難しさを示し、Grok Build の公開や Agents API の実行先の選択肢は、一部の移行を容易にする方向の材料です。[SpaceX目論見書](https://content.spacex.com/cms-assets/FINAL_Documents%20and%20Updates/SpaceX%20-%20EU%20Prospectus%20%28Approved%20by%20Bafin%29%20-%20June%205%2C%202026.pdf)、[Build公開](https://x.ai/news/grok-build-open-source)、[Agents API](https://openai.com/index/introducing-the-agents-api/)。

このシナリオが強まるのは、利用企業が値上げ・条件変更に直面しても移行できず、供給者の利益率と顧客維持が同時に上がる場合です。逆に、同品質の代替へ短期間で移れ、新規の提供企業にも利益が残れば弱まります。モデルを替える操作だけでなく、データ・接続・監督の移行費を見ます。

### W3：知的作業へのアクセスが広がる

安価なモデルと再利用できる実行ソフトがあれば、以前は専門家や大きな開発予算が必要だった作業に小企業や個人が参加できます。Sonnet 5 の価格維持、Grok 4.6 の価格、Build のコード公開、Seedance 2.5 の制作機能は、この経路の入口を支えます。[Sonnet](https://www.anthropic.com/news/claude-sonnet-5)、[Grok](https://x.ai/news/grok-4-6)、[Seedance 2.5](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5)。

制約は、安い利用料でも品質確認、顧客獲得、権利処理、運用の費用が残ることです。動画を作れることと広告成果が得られること、アプリを作れることと継続して保守・販売できることは別です。アクセスが広がるほど成果物が増え、販売価格が下がる可能性もあります。

短期は同じ仕事を同じ品質で終える費用、中期は小規模事業者の参入・継続・利益、長期は教育や専門サービスへのアクセスを見ます。W2とW3は両立し得ます。利用者の入口が安くなっても、計算資源や集客の持ち主に利益が集まる場合があるためです。

### W4：仕事以外の所得とサービスが生活を支える

AIで一部の労働需要が減り、新しい職への移行が追いつかない場合、給付、保険、公共サービス、資産所得が生活を支える割合を増す経路です。採用の入口の縮小は検討の理由になりますが、米国の研究だけで日本にこの制度移行が必要・実現済みと断定できません。

今回確認した資料では、AIによる恒常的な所得減を補う新しい全国制度の支給額・受給者・生活改善を比較可能な形で把握していません。ここは「制度がない」という断定ではなく、実施結果を収集できていないという判断です。AI企業の成長や安全規制を、給付実績の代用品にはしません。

短期は失職と再就職の間の所得、中期は申請条件・支給開始・利用率・財源、長期は実質的な生活水準を見ます。再就職後の賃金が回復するなら労働を中心とした経路が強まり、給付が実際に不足を埋めればW4の根拠が増えます。政策の発表と利用できる制度を分けることが読者の判断に直結します。

### W5：所有と分配のルールそのものが変わる

この経路には、計算資源・モデル・データ・利益への権利について、公共や共同の所有・決定権が制度として広がることが必要です。国が監督するだけで所有が変わったことにはならず、xAI が SpaceX に入る企業買収も公共化とは異なります。[xAIの買収発表](https://x.ai/news/xai-joins-spacex)。

カリフォルニアの9月18日の行政命令は、独立した検証や監査を強める方向の材料です。しかし、これは安全を管理する制度であり、計算資源や会社の所有権を公共に移す決定ではありません。[州政府説明](https://www.gov.ca.gov/2026/09/18/governor-newsom-issues-executive-order-to-accelerate-independent-oversight-and-advance-the-creation-of-an-ai-kill-switch/)。

3〜10年の探索では、法的な権利の変更、持続する財源、利用者が意思決定に参加できるか、供給と分配が継続するかを追います。公開コードの存在も、会社の利益への所有権を利用者へ与えるものとは限りません。現在の資料はW5の実現を強く支持する段階にはありません。

### 読者の判断へどう結び付けるか

会社は、AIが安くなることと、自社に利益が残ることを別に検証する必要があります。顧客との関係、業務知識、品質の責任を保持しつつ、モデルや実行環境を替えられる構成の価値が高まります。個人には、作業速度だけでなく、顧客の問題を定め、結果を検証し、別の職や取引先へ移れる能力が重要になるという含意があります。これは現在の構造からの推論であり、本人の所得を測った結論ではありません。

社会については、既存社員の効率化と新人の経験形成を一緒に評価する必要があります。入口の業務を自動化しても育成の代替経路がなければ、将来の熟練者を作る仕組みが弱くなる可能性があります。訓練の実施だけでなく、修了後の採用・賃金まで追います。
