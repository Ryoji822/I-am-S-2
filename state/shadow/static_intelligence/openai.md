# OpenAI：消費者の利用基盤から、企業の仕事を動かす基盤へ

基準日：2026年9月21日。再調査・改稿：9月22日（日本時間）。以下は会社発表、製品仕様、分析を区別した企業資料です。随時更新される料金表だけは9月22日の確認値を明記します。

## 会社の全体像

OpenAI は ChatGPT を個人・法人に提供し、開発者にはモデル API とエージェントの実行機能を販売しています。企業に対する接点は、従業員が使う ChatGPT、開発者が使う Codex、自社製品に組み込む API の三つです。同社はこの接点を統合する方針を示しており、モデルを選ぶだけでなく、仕事を開始して結果を受け取る場所を提供しようとしています。[事業・資金調達の説明](https://openai.com/index/accelerating-the-next-phase-ai/)

この会社を理解するうえで押さえるべき点は、既に大きな消費者基盤を持つことと、その規模を企業向けの継続収益へ移す途中であることです。3月31日の自社公表では ChatGPT の週間利用者は9億人超、有料契約者は5,000万人超、法人事業は売上の40%超でした。これは公表当時の値で、9月の実績や監査済み決算ではありません。[同発表](https://openai.com/index/accelerating-the-next-phase-ai/)

**現在の評価は、企業向け製品の幅と販売力は強い一方、それが利用企業の利益や OpenAI 自身の持続的な利益にどれだけ結び付くかは別途確認が必要、というものです。** 製品の提供は確度が高く、優位が長く続くという評価は中程度です。収益・利用の公表には当事者の利害があり、顧客維持率や利益率を同じ基準で比較できる資料が不足しています。

## 製品、顧客、提供形態

OpenAI の企業に対する接点は、従業員が使う ChatGPT、開発者が使う Codex、自社製品に組み込む API の三つに、9月末以降の公表で広告収益とプロアクティブな作業支援が加わりました。

| 製品・機能 | 顧客が購入するもの | 事業上の役割 |
|---|---|---|
| ChatGPT／法人向けプラン | 会話、調査、資料作成などを行う利用環境 | 個人の日常利用から企業契約につながる入口 |
| ChatGPT の広告 | 9月23日に ChatGPT Ads を東南アジア・台湾へ拡大。10月5日に視覚的な広告フォーマット、計測ツール、アトリビューション提携、ブランド適合性を拡大 | 利用者の注意を広告主へ販売する収益経路 |
| Codex | コードベースを読み、変更・確認を進める開発用エージェント | 開発者の継続利用と実務への接続 |

| GPT-6 Sol／GPT-6 Luna | 9月22日発表。能力と費用の異なるバランスで日常業務にフロンティア級の知能を届ける2モデル | 仕事の種類に応じた使い分けと費用管理 |
| GPT-6.1 Sol | 9月29日発表。コーディング・コンピュータ利用・専門業務で Astra に近い知能を、Astra の標準API入出力トークン価格の5分の1で提供と説明 | 大量利用を見込んだ低価格帯の拡充 |
| Agents API | 9月10日公開ベータ。Codex の実行機構を使ったクラウドエージェント | セッション、ツール、実行環境の管理を企業の実装に取り込む |
| Astra for Law | 9月17日発表。法務向け検索・指示・文脈を加えた Astra | 業界の業務に近い層で直接販売とパートナー販売を広げる |

| Daybreak | セキュリティ運用に関わる提供。Sophos の脅威調査の事例（10月9日）とウクライナ政府へのアクセス拡大（9月23日）で名称を確認 | 政府・セキュリティ分野への専門提供（範囲・料金は未確認） |

出典：[Astra](https://openai.com/index/gpt-6-astra/)、[Agents API](https://openai.com/index/introducing-the-agents-api/)、[法務向け発表](https://openai.com/index/astra-for-law/)。9月22日以降の製品項目（GPT-6 Sol/Luna、GPT-6.1 Sol、dots、広告の拡大、10月7日の GPT-6 と Intelligent UI の ChatGPT での世界展開、Daybreak 関係）は [OpenAI の公式フィード](https://openai.com/news/rss.xml)の標題・説明文で確認したもので、記事本文は未確認です。9月29日の DevDay では Astra、ChatGPT、Codex、API、セキュリティ関連を含む20以上の発表があったと公表されています。

Agents API は長いセッション、ツール利用、複数エージェントの仕事を扱います。実行環境は OpenAI ホストだけでなく、自社環境やパートナー環境を選べます。基盤となる Codex のコードを公開する方針も示されています。ここから読み取れるのは「実行環境の選択肢がある」ことです。モデルやセッション履歴、認証、評価を含むシステム全体が他社へ無加工で移せることまでは意味しません。移行の難しさはどの機能に依存するかで変わります。

Astra for Law には Harvey、Legora のような API 顧客も含まれます。業界向け製品の拡張は、既存の業務ソフト会社と競合する可能性と、それらの会社の供給元になる可能性を同時に持ちます。

広告の拡大は、消費者の注意力を広告主へ販売する収益経路を企業契約と並べて持つ変更です。Radisson Hotel Group が Accenture と組み ChatGPT 内でホテルの検索・比較・予約を助けるプラグインを構築した事例も、顧客接点が ChatGPT 側に集まる方向の公表例です。いずれも収益・利用規模の数値は今回の資料にはありません。

事実は事業・仕事・所得の三層に別々に効きます。事業では、広告収益の追加は法人契約以外の収益経路を広げ、消費者接点の維持力を高めます（MET-FIRM、W2 の材料）。仕事では、dots・Agents API・Astra for Law の拡張は実行と判断を提供側が担う範囲を広げ、業務ソフト会社との競合と供給の両方を進めます（LINK-OWNERSHIP-PROFIT）。所得では、GPT-6 Sol/Luna・GPT-6.1 Sol の低価格帯は小規模事業者や個人が同じ作業に参加する費用障壁を下げる方向です（W3、MET-COST）。別の説明として、発表の集中は投入計画の表明であり利用・更新・採算の実態を反映しない可能性、広告は既存の検索・SNS 広告予算の奪い合いで総需要を増やさない可能性があります。

残る限界：新規項目の根拠は公式フィードの標題・説明文のみで、記事本文は個別URLが403等のため未確認です。広告の掲載条件・価格、Daybreak の提供範囲・契約条件、dots の利用条件、Intelligent UI の到達範囲と品質は不明です。利用規模・更新率・採算を示す数値はありません。見直し条件は、広告掲載条件の公表、Daybreak・dots の契約条件の確認、第三者による利用実態調査の出現です。

9月22日に確認した公式 API 料金表の Standard・短いコンテキストの価格です。単位は100万トークン当たりの米ドル。入力・出力とも通常料金で、キャッシュ、長いコンテキスト、Batch、Fast mode、ツール等の費用は別条件です。

- 9月22日：GPT-6 Sol と GPT-6 Luna を、能力と費用の異なるバランスで日常業務に提供する2モデルとして発表。[公表](https://openai.com/news/rss.xml)
- 9月22日：GPT-6 のプロンプトキャッシュ改善を公表。キャッシュヒット率の向上、新しい診断、明示的なブレークポイントを掲げ、レイテンシと費用の低減を主張。[公表](https://openai.com/news/rss.xml)
- 9月29日：GPT-6.1 Sol を発表。コーディング・コンピュータ利用・専門業務で Astra に近い知能を、Astra の標準API入出力トークン価格の5分の1で提供と説明。5分の1という位置づけは OpenAI の主張で、API 料金ページ上の実価格は今回未確認。[公表](https://openai.com/news/rss.xml)

顧客側の費用主張（いずれも OpenAI 掲載で独立検証なし）：
- V7 は GPT-5.6 Luna による78%のコスト削減と精度向上を主張（9月21日）。
- Ringg は GPT-5.6 による多言語顧客対応を GPT-4.1 比で90%低いコストと主張（9月23日）。
- LegalOn は Astra・Sol・Luna をタスクに合わせて使い分け、推定日次 Codex 費用を65%削減しつつ開発速度を維持したと主張（10月8日）。
- Asana はブラウザエージェントのテストで76分の1のコスト・5倍の速度を主張（10月9日。標題は GPT-6.1 Sol、説明文は GPT-6 Astra と述べており、記事本文は未確認）。

これらの業務・分母はそれぞれ異なり、一般の価格水準や別の会社の利益への換算には使えません。

価格差は利用企業の選択に直結します。例えば単価の高いモデルでも、再試行や人の手直しが少なければ仕事一件当たりでは安くなる場合があり、高い推論設定、長いセッション、確認待ちを含めると支出が増えることもあります。納品物の合格率と人の確認時間まで含めて選ぶ必要がある、という9月22日時点の読み方は変更しません。低価格帯の追加とキャッシュ改善は、使い分けの選択肢を増やす方向の公表です。

価格帯の多層化とキャッシュ改善は、同品質の仕事当たり費用（MET-COST）を下げる方向の公表で、W3（知的作業が安く広く使える）の入口条件に関わります。顧客側の費用主張は、モデルを使い分けて総費用を管理する運用（LegalOn）や低価格帯での試験（Asana）という実務パターンの示唆です。ただし分母は各社の特定業務で、固定5業務・品質基準・基準4週間・各業務20件という F-S01 の前提が決まらないため、これらの数値を予測の基準値には使えません。別の説明として、低価格帯の公表は上位モデルへの誘導を含む販売戦略でもあり、実務の総費用は再試行・確認時間・移行費用で決まる可能性があります。

残る限界：9月22日以降の料金ページ再確認は未実施で、GPT-6 Sol/Luna・GPT-6.1 Sol の実価格・プロモーション条件は不明です。5分の1・78%・65%・90%・76分の1はすべて提供側・顧客側の主張で、記事本文は未確認、独立検証もありません。低価格帯の品質が同じ仕事で維持されるかは固定業務試験の設計待ちです。見直し条件は、料金ページの直接再確認と、F-S01 の不足項目（固定5業務、品質基準、基準4週間、各業務20件）の確定です。

## 売上、資金、計算資源

3月31日、OpenAI は1,220億ドルのコミット済み資金と、資金調達後評価額8,520億ドルを公表しました。同時に月間売上20億ドル、約47億ドルの未使用リボルビング融資枠を説明しています。調達額・評価額・月間売上・融資枠はそれぞれ違う量です。調達額を売上、評価額を手元資金として扱ってはいけません。[資金調達発表](https://openai.com/index/accelerating-the-next-phase-ai/)

同発表で示す計算資源の調達先には Microsoft、Oracle、AWS、CoreWeave、Google Cloud があり、半導体も NVIDIA を中心に複数の方式を組み合わせています。顧客には統一された製品を提供しながら、供給元は分散させる構造です。供給の確保は成長を支えますが、契約額や設備規模だけで利益を評価することはできません。

分析上の争点は、利用拡大に伴う収入が、推論費用・研究費・インフラ負担を上回るかです。規模が大きいほど単価が下がる経路と、能力向上や安全監視のため計算量が増える経路が併存します。9月3日の安全説明では、Astra のツール利用時の監視に相応の計算費用をかけると公表しています。[Astra の安全説明](https://openai.com/index/safety-overview-gpt-6-astra/)

## 能力と運用上の制約

Astra の発表は、コンピューター操作、専門業務、科学、開発における性能向上を中心にしています。掲載されたベンチマークや顧客の初期評価は、能力が広がった根拠にはなりますが、あらゆる企業で人の仕事を代替できる実績ではありません。与えた道具、試行回数、推論設定、合格条件が変われば結果も変わります。[能力評価](https://openai.com/index/gpt-6-astra/)

OpenAI は Astra のサイバー能力を自社の Preparedness Framework で Critical と評価し、安全対策と監視を強化しました。同時に、書かれた推論の監視しやすさが Sol より低下した試験結果も開示しています。モデルが賢くなることと、全ての行動を監督しやすくなることは一致しません。[安全説明](https://openai.com/index/safety-overview-gpt-6-astra/)

利用企業への含意は、許可範囲、外部への書き込み、機密情報へのアクセス、異常時の停止を仕事ごとに設計する必要があるということです。事業に組み込んだ後の停止や制限変更は、単なる使い勝手の問題から納期・顧客対応の問題に変わります。

## 競争上の位置と別の解釈

OpenAI の強みは、消費者の利用基盤と開発者の仕事場を持ち、モデル・実行管理・業界向け機能を同じ提供元で揃えられることです。企業は部品を組み合わせる負担を減らせます。その反面、提供元の仕様変更に業務が左右される範囲も広がります。

| 説明 | 支える材料 | この説明だけでは説明できないこと |
|---|---|---|
| 企業の標準的な仕事場へ進む | ChatGPT、Codex、Agents API、法務向け製品が同じ業務につながる | 発表だけでは契約更新・利益・業務完了率を証明できない |
| 顧客の実装負担を減らす共通部品になる | 自社・パートナーの実行環境を選択でき、業務ソフト企業にも供給する | 履歴・運用・評価の移行まで容易とは限らない |
| 利用規模を維持するため製品と資金を拡張している | 大きな資金需要、広い価格帯、複数の供給元 | 拡張が苦しい採算の結果なのか、成長投資なのかは公表値だけでは決まらない |

現時点では最初の二つが同時に進んでいると読むのが妥当です。「閉じた独占」か「完全に開いた部品」かの二択にすると、実行環境の開放とサービスへの依存が同居する実態を見失います。
